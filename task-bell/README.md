# 任务完成通知

DSH 的系统通知插件，支持 Web Push：关闭网页或 Edge「安装为应用」窗口后仍可接收任务完成通知。网页打开时也保留实时事件通道，两条通道由 Service Worker 持久化去重。

在 **设置 → 通用 → 任务完成通知** 开启。旧版本升级后，点击 **开启后台推送** 建立当前浏览器的订阅，再点击 **测试通知**。测试通过真实推送服务发送，发送被服务接受并不代表 Windows 已展示横幅。

点击通知会先激活同源、同路径的已有窗口，再发送会话路由消息；页面未响应时通过完整会话 URL 导航，没有窗口时打开页面。支持普通标签页和 Edge 应用窗口，最终激活行为由浏览器和操作系统控制。

需要 HTTPS、通知授权、客户端和 DSH 服务能联网，以及 DSH 服务持续运行。Edge 推送使用浏览器提供的推送端点；不需要将 DSH 暴露到公网。Windows 勿扰模式、网络限制、关机或强制停止浏览器后台组件会影响接收和横幅。声音完全交给系统通知设置。

推送订阅和 VAPID 密钥保存在 DSH 凭据服务的 `task-bell/web-push-v1` 记录，密钥不放进源码或插件配置。任务推送保留 5 分钟，测试推送保留 1 分钟；过期订阅自动清理，网络或推送服务的临时失败最多重试一次。关闭设置开关会移除当前浏览器的服务端订阅并取消浏览器订阅。

浏览器只在用户点击开启时申请授权和创建订阅；代理不能代替用户完成该授权。推送载荷包含任务结束状态、会话标识和打开地址，不包含会话正文。点击通知需有有效 DSH 登录状态；登录已过期时，DSH 仍会要求重新登录。

验证：`node --test push.test.mjs worker.test.mjs`，以及 `node verify.mjs`。测试覆盖真实 Web Push 加密/解密、订阅与密钥跨实例持久化、过期清理、端点校验、鉴权、防跨站提交、双通道去重及通知点击聚焦/路由/导航兜底。实际 Edge/Windows 的后台接收和窗口激活需在用户设备验证。
